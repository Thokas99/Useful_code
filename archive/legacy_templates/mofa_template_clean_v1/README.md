# MOFA_TEMPLATE_CLEAN

**Status:** Reusable MOFA template; not a fitted project model.

## Purpose and status

This folder is a generic, notebook-first MOFA template distilled from the live TCGA-LUAD notebooks. It is a project scaffold, not a fitted model and not a record of TCGA-LUAD sample counts. Replace `PROJECT_ID`, input tables, feature contracts, group labels, and output paths before execution. Preserve the configured copy with the generated model.

## Methods

### Project setup and object contracts

`00_project_setup.qmd` defines the project identifier, cohort label, expected sample-ID length, score column, and class column used by later notebooks. It constrains thread environment variables to one where configured and sets a large future global size for matrix operations. These settings make execution more predictable but do not replace a package environment lockfile.

The required handoffs are a matched multi-omics manifest, scored metadata, a serialized list of model input views, an HDF5 MOFA model, factor and association tables, group-summary tables, and factor/weight heatmaps. The source deliberately keeps assay-specific cleaning and biological interpretation in notebooks and uses `helpers/helpers_from_MOFA.R` only for repetitive matrix operations.

### Input preparation

`01_multiomics_input_prep.qmd` reads matched RNA, miRNA, methylation, mutation, and RPPA tables, normalizes sample-column identifiers, checks the assay/sample contract, and writes the manifest plus matched tables under `input/tables/`. The template assumes that the views are already matched at the sample level; it does not download GDC data or infer a match from arbitrary sample names.

### Signature scoring

`02_signature_scoring.qmd` reads the matched RNA matrix, sample metadata, and a configured signature gene table. Its helper creates an edgeR DGEList, retains genes with CPM >1 in at least five samples, estimates TMMwsp normalization factors, and computes logCPM with prior count 1. Signature genes are intersected with the matrix, the available-gene expression is averaged by sample, the resulting score is standardized, and the configured class is assigned. The code records the score and coverage needed by downstream modelling. This is a template score contract, not a universal C1 definition.

### View filtering and MOFA input

`03_mofa_model.qmd` computes logCPM for RNA and miRNA, loads methylation, mutation, and RPPA views, and keeps the 5,000 most variable features per view using the helper's non-missingness requirement. All views are restricted to common sample identifiers, and the aligned list is saved as `{PROJECT_ID}_mofa_input.qs2`. The notebook then creates a MOFA object, obtains default options, sets `num_factors = 10`, prepares the model, and runs it to `{PROJECT_ID}_mofa_model.hdf5`.

The template exports all sample factor values, per-view factor weights, variance/explanation summaries, factor heatmaps, top-weight heatmaps for factors 1–5 with 30 displayed features, and group comparisons using a configured C1 score/class. The group summaries calculate median differences for continuous views and group-frequency differences for mutation features. The template uses MOFA default likelihood and training settings unless a project copy overrides them; it is therefore distinct from the live TCGA model, which uses four explicit likelihoods, 15 factors, disabled view scaling, float32 storage, seed 12345, slow convergence, and 1,500 iterations.

## Object contracts

- `input/tables/PROJECT_ID_matched_multiomics_manifest.tsv`: sample/view manifest generated by input preparation.
- `input/tables/RNA_MATCHED.tsv`, `MIRNA_MATCHED.tsv`, `METHYLATION_MATCHED.tsv`, `MUTATION_MATCHED.tsv`, `RPPA_MATCHED.tsv`: sample-matched view matrices.
- `output/tables/PROJECT_ID_scored_metadata.tsv`: signature score, class, and sample metadata.
- `output/objects/PROJECT_ID_mofa_input.qs2`: aligned, feature-filtered view list.
- `output/objects/PROJECT_ID_mofa_model.hdf5`: fitted MOFA model.
- `output/tables/PROJECT_ID_mofa_factors.tsv`: sample-level factor values.
- `output/tables/PROJECT_ID_factor_score_associations.tsv`: factor associations with the configured score/class.
- `output/tables/mofa_group_summaries/`: view-specific group comparison exports.
- `output/figures/mofa_heatmaps/`: factor and top-weight heatmaps.

## Software and reproducibility

The template is R/Quarto-based and uses MOFA2, edgeR, qs2, readr, ggplot2, tidyr, tibble, purrr, and helper functions. It has no data-download step, no lockfile, and no cohort-specific package/version manifest. Before using it for a study, record the matrix generation, assay-specific transformations, genome/annotation release, exact configuration, package versions, and the input checksums.

## Method reconstruction

Populate the five matched view tables and metadata, run input preparation, run the edgeR/TMMwsp signature scoring notebook, then run the MOFA model notebook. Verify common sample identifiers and retained feature counts before fitting. Save the configuration and the generated manifest beside the HDF5 model, then export factors, weights, variance explained, and group summaries. Do not describe the default ten-factor template as the live TCGA-LUAD fifteen-factor model.
